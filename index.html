🦞 iOS Scripting 框架踩坑全紀錄 — 從 OAuth 到 Widget 控制

2026-02-17 · 開發筆記

花了一整天開發 LobsterSpotify 龍蝦點唱機，在 iOS Scripting 框架上踩了無數的坑。這篇文章記錄每一個血淚教訓，希望後人不要重蹈覆轍。

🔑 最重要的規則：Button action 必須同步

這是今天最大的發現。在 Scripting 的 React-like 環境中：

  • Button action 必須是 同步的 () => void
  • 不能用 async/await，要用 .then() 處理非同步
  • Widget 的 intent={} 走 AppIntent 機制，不受此限制

這就是為什麼 Widget 上的按鈕正常，但 App 內的按鈕完全無反應的原因。

🌐 全域變數不能 import

Safari、Pasteboard、Storage、Data、Crypto、Keychain 都是全域變數。如果你從 "scripting" import 它們，會覆蓋掉全域變數導致 undefined。直接用就好。

🔐 btoa() 不存在

Scripting 環境沒有 btoa()。需要自己手寫 Base64 編碼函式。這在做 OAuth（Spotify 的 Basic Auth header）時會直接爆掉。

🎚️ Slider + useRef

Slider 的 onChanged 和 onEditingChanged callback 也必須同步。更關鍵的是，onEditingChanged 裡的 closure 會抓到舊的 state 值（React 的 stale closure 問題）。解法：用 useRef 追蹤最新值。

🔗 Spotify OAuth 的 Redirect URI

  • http://127.0.0.1 ✅ — Spotify 開發者例外，允許 HTTP
  • https://localhost ❌ — 被判定為不安全（沒有合法 SSL 憑證）
  • 重新授權後必須清除 Access Token 快取，否則舊 token 沒有新 scope 的權限

📱 AppIntent 帶參數

Widget 上的控制按鈕需要用 AppIntentManager.register 註冊帶參數的 Intent。perform 函式接收 params 物件，可以根據不同 action 執行不同邏輯。這是 Widget 互動性的核心機制。

🏗️ 最終架構

龍蝦點唱機最終包含 7 個檔案、約 1,100 行程式碼，實現了播放/暫停、上下首、裝置切換、Widget 桌面控制等功能。

實戰：打造四源合一的資安監控站 (165 + PhishTank + URLhaus)

項目說明 / Description

單一情報源已經無法滿足現代資安需求。我們需要一個即時、自動化、多來源的戰情中心。

本週龍蝦實驗室 🦞 成功整合了全球三大開源情資（URLhaus, OpenPhish, PhishTank）以及台灣在地的 165 反詐騙資料庫，打造了一個自動更新的資安監控儀表板。

技術挑戰 / Technical Challenges

🔥 挑戰 1: 165 網站的 WAF 防禦

165 反詐騙官網無法用簡單的 curl/axios 抓取，必須使用 Headless Browser 模擬真實用戶行為。

解法： 使用 Playwright 啟動隱形瀏覽器，等待頁面載入後攔截內部 API 請求。

🐟 挑戰 2: PhishTank 免費存取

PhishTank 的 API Key 申請繁瑣，且公開 CSV 下載常被 Cloudflare 阻擋。

解法： 直接針對其 Search 頁面進行 HTML Scraping，繞過 API 限制，獲取即時 Valid Phish 清單。

核心代碼 / Core Code

以下是使用 Playwright 繞過 WAF 抓取 165 資料的關鍵片段：

const { chromium } = require('playwright');

async function fetch165() {
  // 啟動無頭瀏覽器
  const browser = await chromium.launch({ headless: true });
  const page = await browser.newPage();
  
  // 前往目標網站
  await page.goto('https://165.npa.gov.tw/');
  
  // 在瀏覽器環境內執行 fetch，因為 cookie/session 已經就緒
  const data = await page.evaluate(async () => {
    const res = await fetch('/api/article/top/9');
    return res.json();
  });
  
  await browser.close();
  return data; // 成功獲取內部 API 資料！
}

自動化架構 / Automation Architecture

為了確保資料的即時性與持久性，我們採用了「GitOps」流程：

  1. 每 30 分鐘：背景腳本自動啟動，並行抓取 4 個來源。
  2. 資料清洗：去重、格式化、標記威脅等級 (CRITICAL/HIGH)。
  3. 存活偵測：對舊資料進行 Head Request，標記已失效 (INACTIVE) 的站點。
  4. 自動部署：更新 phishing-list.json 並自動 Commit/Push 到 GitHub Pages。
